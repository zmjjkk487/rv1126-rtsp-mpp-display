📐 Lesson 1：数据流动全景图

教学目标：闭眼能讲出从摄像头到屏幕的 8 段数据链路，知道每一段数据长什么样。

你项目的完整链路

🌐 摄像头
 │  H.264 编码 光→电→压缩
 │  1920×1080 YUV → 4Mbps H.264 码流
 ▼
📡 网络
 │  RTP 分包  H.264 NAL → RTP 包 (MTU 1500)
 │  每帧 ~10-50 个 UDP/TCP 包
 ▼
🔌 rtspsrc
 │  RTSP 握手 + 收包  拼 RTP → 还原 H.264
 │  输出: video/x-h264, stream-format=avc
 ▼
📦 rtph264depay
 │  解 RTP 封装  去 RTP 头, 重组 NAL 单元
 │  输出: video/x-h264, stream-format=byte-stream (Annex-B)
 ▼
🔧 h264parse
 │  解析 H.264 语法  识别 SPS/PPS/IDR/P 帧
 │  输出: video/x-h264, parsed=true
 ▼
🧠 mppvideodec
 │  MPP 硬件解码  H.264 → YUV420 (NV12)
 │  1920×1080 压缩 → 3.1MB 原始帧 (VPU 硬件, ~0% CPU)
 │  输出: video/x-raw, format=NV12 (dmabuf)
 ▼
📥 appsink
 │  取帧回调  从 GStreamer 管线拉出一帧 NV12
 │  GstVideoMeta 取真实 stride: hs=1920, vs=1088
 ▼
🎨 RGA
 │  硬件颜色转换 + 缩放  NV12 → BGRX_8888
 │  1920×1080 → 720×405 (等比) + 黑边 720×1280
 │  硬件 blit: ~2-4ms, ~0% CPU
 ▼
🖥️ fbdev
 │  显存写入  memcpy back→framebuffer mmap
 │  720×1280×4 = 3.7MB/帧
 ▼
📱 MIPI LCD
   屏幕显示 (720×1280, 32bpp)

关键数据格式在每个节点的变化

节点格式大小 (1080p)硬件/软件
摄像头输出H.264 压缩流~4 Mbps (~16KB/帧)摄像头 ISP + 编码器
rtspsrc → depay → parseH.264 Annex-B~16KB/帧CPU (轻量)
mppvideodec 输出NV12 (Y + UV)1920×1088×1.5 = 3.13 MBVPU 硬件
RGA 输出BGRX_8888720×1280×4 = 3.69 MBRGA 硬件
fbdev 写入RGB (32bpp)3.69 MBCPU memcpy 3-10%
🔑 关键洞察：数据从 16KB（压缩）膨胀到 3.7MB（原始）→ 膨胀 ~230 倍。这就是为什么需要硬件解码和硬件转换——纯 CPU 处理 3.7MB/帧 × 25fps = 92MB/s 的数据，Cortex-A7 根本扛不住。

你项目中的三条内存路径

硬件零拷贝 dmabuf 路径（实际在用）
MPP 输出 dmabuf → GStreamer 传 fd → appsink 取 GstVideoMeta → gst_buffer_map 取指针 → RGA 用 virAddr+mmuFlag 读 → RGA 写 back buffer。数据全程不经过 CPU 拷贝。
CPU 回退 软件转换（RGA 不可用时）
MPP 输出 → CPU 读 NV12 → nv12_to_rgb888() 逐像素 BT.601 → 写 back buffer。1080p 下 ~80% CPU，作为紧急兜底。
帧缓冲 back buffer → 显存（每帧最后一跳）
RGA 写完 back buffer 后 → memcpy 到 /dev/fb0 mmap 映射的显存区域。这是物理上不可避免的一次拷贝（从 DDR 到显存控制器），约 1-3ms。
