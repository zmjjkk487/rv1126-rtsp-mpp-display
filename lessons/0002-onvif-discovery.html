📡 Lesson 2：ONVIF 摄像头自动发现原理

问题：客户拿到板子，不知道摄像头的 RTSP 地址填什么。
目标：板子上电 → 自动扫描局域网 → 列出所有摄像头 → 客户点一下就能看画面。

ONVIF 是什么

ONVIF = Open Network Video Interface Forum。一个行业协会标准，几乎所有 IP 摄像头都支持。

它定义了一套基于 SOAP/XML 的 Web Service 协议，让你可以：发现摄像头、获取 RTSP 地址、控制云台、修改配置。

核心原理 ONVIF 建立在三个标准协议之上：
① WS-Discovery (UDP 组播) — 在局域网里找到摄像头
② SOAP/XML (HTTP POST) — 向摄像头请求 RTSP 地址
③ WS-Security (HTTP Header) — 用户名密码认证

第一步：WS-Discovery 发现摄像头

原理：发一条 UDP 广播，摄像头回复自己的信息

板子 (192.168.50.132)                  摄像头 (192.168.50.168)
    │                                        │
    │  UDP → 239.255.255.250:3702             │
    │  SOAP Probe: "谁支持 ONVIF？"            │
    │ ─────────────────────────────────────→  │
    │                                        │
    │           UDP ← 192.168.50.168:3702     │
    │           SOAP ProbeMatch:               │
    │           "我是海康 DS-2CD1021,          │
    │            我的服务在                      │
    │            http://192.168.50.168/onvif/   │
    │                      device_service"      │
    │  ←───────────────────────────────────── │

实际发送的 XML（你的 C 代码要构造这个）

<?xml version="1.0" encoding="utf-8"?>
<e:Envelope
  xmlns:e="http://www.w3.org/2003/05/soap-envelope"
  xmlns:w="http://schemas.xmlsoap.org/ws/2004/08/addressing"
  xmlns:d="http://docs.oasis-open.org/ws-dd/ns/discovery/2009/01"
  xmlns:dn="http://www.onvif.org/ver10/network/wsdl">
  <e:Header>
    <w:MessageID>uuid:1234567890-abcd</w:MessageID>
    <w:To>urn:docs-oasis-open-org:ws-dd:ns:discovery:2009:01</w:To>
    <w:Action>http://docs.oasis-open.org/ws-dd/ns/discovery/2009/01/Probe</w:Action>
  </e:Header>
  <e:Body>
    <d:Probe>
      <d:Types>dn:NetworkVideoTransmitter</d:Types>
    </d:Probe>
  </e:Body>
</e:Envelope>

这条 XML 通过 UDP socket 发到 239.255.255.250 端口 3702。这是一个组播地址——同网段所有 ONVIF 设备都会收到。

摄像头回复的内容（你的 C 代码要解析这个）

<e:Envelope ...>
  <e:Body>
    <d:ProbeMatches>
      <d:ProbeMatch>
        <w:EndpointReference>
          <w:Address>urn:uuid:7e2a1b3c-...</w:Address>
        </w:EndpointReference>
        <d:Types>dn:NetworkVideoTransmitter</d:Types>
        <d:XAddrs>
          http://192.168.50.168/onvif/device_service
        </d:XAddrs>
        <d:MetadataVersion>1</d:MetadataVersion>
      </d:ProbeMatch>
    </d:ProbeMatches>
  </e:Body>
</e:Envelope>

核心字段就一个：XAddrs — 摄像头的 ONVIF 服务地址。拿到这个，第二步就有目标了。

兼容性技巧（来自生产项目）

问题解法
不同厂商用不同 WS-Discovery 版本同时发 6 种 Probe（2005×2009×3 类 Type）
部分摄像头不响应组播额外单播扫同网段 254 个 IP
XAddrs 可能包含多个 URL优先选含 /onvif/device_service 的那个
重复响应按 XAddrs host 去重

第二步：获取 RTSP 地址

拿到 http://192.168.50.168/onvif/device_service 后，发 HTTP POST（Content-Type: application/soap+xml）。

2a. GetCapabilities — 问摄像头支持什么功能

POST /onvif/device_service HTTP/1.1
SOAPAction: http://www.onvif.org/ver10/device/wsdl/GetCapabilities

<s:Envelope xmlns:s="http://www.w3.org/2003/05/soap-envelope">
  <s:Body>
    <tds:GetCapabilities xmlns:tds="http://www.onvif.org/ver10/device/wsdl">
      <tds:Category>All</tds:Category>
    </tds:GetCapabilities>
  </s:Body>
</s:Envelope>

返回 XML 里找 <tt:Media><tt:XAddrs>http://... — 这是媒体服务的地址。

2b. GetProfiles — 列出所有码流配置

POST /onvif/Media HTTP/1.1
SOAPAction: http://www.onvif.org/ver10/media/wsdl/GetProfiles

<s:Envelope ...>
  <s:Body>
    <trt:GetProfiles xmlns:trt="http://www.onvif.org/ver10/media/wsdl"/>
  </s:Body>
</s:Envelope>

返回每个 profile 的 token + name（如 "mainStream"/"subStream"）+ 分辨率。

2c. GetStreamUri — 获取实际 RTSP URL

POST /onvif/Media HTTP/1.1
SOAPAction: http://www.onvif.org/ver10/media/wsdl/GetStreamUri

<s:Envelope ...>
  <s:Body>
    <trt:GetStreamUri xmlns:trt="http://www.onvif.org/ver10/media/wsdl">
      <trt:StreamSetup>
        <tt:Stream xmlns:tt="http://www.onvif.org/ver10/schema">RTP-Unicast</tt:Stream>
        <tt:Transport xmlns:tt="http://www.onvif.org/ver10/schema">
          <tt:Protocol>RTSP</tt:Protocol>
        </tt:Transport>
      </trt:StreamSetup>
      <trt:ProfileToken>profile1</trt:ProfileToken>
    </trt:GetStreamUri>
  </s:Body>
</s:Envelope>

返回 <tt:Uri>rtsp://192.168.50.168:554/stream0</tt:Uri>

💡 实际只需要三步：Probe → GetProfiles → GetStreamUri。
大多数摄像头 GetCapabilities 可以跳过（media 地址就是 /onvif/Media）。

认证：如果摄像头有密码？

在 SOAP Header 里加上 WS-Security UsernameToken：

<s:Header>
  <Security xmlns="http://docs.oasis-open.org/wss/2004/01/oasis-200401-wss-wssecurity-secext-1.0.xsd">
    <UsernameToken>
      <Username>admin</Username>
      <Password Type="http://docs.oasis-open.org/wss/2004/01/oasis-200401-wss-username-token-profile-1.0#PasswordDigest">
        
      </Password>
      <Nonce EncodingType="http://docs.oasis-open.org/wss/2004/01/oasis-200401-wss-soap-message-security-1.0#Base64Binary">
        
      </Nonce>
      <Created xmlns="http://docs.oasis-open.org/wss/2004/01/oasis-200401-wss-wssecurity-utility-1.0.xsd">
        2024-01-01T00:00:00Z
      </Created>
    </UsernameToken>
  </Security>
</s:Header>

但很多摄像头也接受 HTTP Basic Auth（Authorization: Basic base64(user:pass)），更简单。先试 Basic，失败再上 WS-Security。

C 实现的可行方案

最小实现 约 500 行 C 代码：
① UDP socket → sendto(239.255.255.250:3702, Probe XML)
② recvfrom + strstr() 解析 XAddrs
③ HTTP POST (BSD socket) → GetProfiles → GetStreamUri
④ libcurl 解析 RTSP URL（或者自己手写 HTTP）
零额外依赖，板上已有 curl。
